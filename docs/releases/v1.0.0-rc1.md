## What is v1.0.0-rc1?

v1.0.0-rc1 is the release candidate for **HMS v1.0.0 GA** — the
first cumulative SemVer release tagged on `main` for the West-African
Hospital Management System. It bundles every roadmap row in the v1.0
horizon (rows 2 – 12 of [docs/roadmap.csv](../roadmap.csv); row 13 is
the cut itself).

| Property | Value |
| --- | --- |
| Tag name | `v1.0.0-rc1` |
| Tagger | the release manager (signed: `git tag -s`) |
| Cut date | `TBD-cut-date` |
| Soak window | 7 days from cut, ending `TBD-soak-end` |
| GA target | `2026-06-23` (`TBD-ga-date` if reschedule) |
| Commit | head of `main` at `TBD-cut-date` |
| Predecessor tag | `v0.1.0` (Feb 2026, first Railway dev deploy) |

Compared to `v0.1.0`, v1.0.0-rc1 represents the leap from
"a deployed Spring Boot app" to "a clinical-flow-complete EMR ready
for hospital pilots in Burkina Faso, Côte d'Ivoire, Senegal, and
Ghana" — see the lane-by-lane summary below.

## What's in this release — by lane

### Clinical Safety

- **CDS Hooks expansion (row 2).** Order-select and
  medication-prescribe hooks added to the `cdshooks/` module with
  RxNorm bindings; integration-tested against the existing
  prescriptions module so a critical interaction surfaces a
  warn-card on the prescriber's screen before the order is signed.
- **Drug-drug interaction check (row 3).** The
  `hms-medication-allergy-check` hook fires on coexisting
  prescriptions in addition to allergy lists; warn-card payload
  carries the interaction severity.

### Pharmacy

- **T-68 offline dispense queue (row 4).** IndexedDB-backed queue
  in the pharmacy UI plus a server-side replay endpoint. Hospitals
  with patchy connectivity can keep dispensing during a network
  outage and the queue drains automatically when the link returns.
  Banner + `aria-live` announcement keep clinicians aware of queue
  state.
- **T-71 Playwright E2E (row 5).** One end-to-end test per dispense
  path: Tier-1 in-house, Tier-2 partner, refill, AMU export. Each
  runs in the `chromium` Playwright project via the existing CI
  workflow.
- **T-72 perf baseline (row 6).** k6 script at 50 concurrent
  dispenses with `p95 < 800ms` recorded in
  [docs/observability/performance-baseline.md](../observability/performance-baseline.md).
  Becomes the regression baseline for v1.1.

### Security

- **Idle session timeout — server-side (row 7).** Last-activity
  tracked in Redis; requests after a 15-minute idle window are
  rejected with `401`; the JWT silent-refresh respects the same
  window, so an idle tab cannot quietly extend the session.
- **Keycloak Phase C cutover (row 8).** `OIDC_REQUIRED=true` flipped
  on UAT and soaked for 7 days, then promoted to prod. The legacy
  `/auth/login` endpoint returns `410 Gone` so any forgotten direct
  POST gets a clear failure rather than silent fallback. Phase C
  closes out the multi-phase Keycloak migration whose runbook lives
  at [docs/runbooks/keycloak-cutover-runbook.md](../runbooks/keycloak-cutover-runbook.md).

### Operations

- **DR runbook (row 9).** [docs/runbooks/disaster-recovery.md](../runbooks/disaster-recovery.md)
  covers Railway snapshot + restore, Postgres point-in-time
  recovery, and rebuild of the observability stack (Grafana Cloud
  OTel + Splunk HEC). First on-call rehearsal scheduled in the soak
  window.

### Accessibility (WCAG 2.1 AA)

- **axe-core / Playwright smoke (row 10).** PR-blocking gate against
  any new `serious` / `critical` axe violation across `/login`,
  `/dashboard`, `/patient-tracker`, `/my-medications`. Implemented
  in [hospital-portal/e2e/a11y.spec.ts](../../hospital-portal/e2e/a11y.spec.ts).
- **Keyboard navigation pass (row 11).** All clinical-flow screens
  reachable + actionable via keyboard. Documented end-to-end in
  [docs/ui/accessibility.md](../ui/accessibility.md). Ships:
  - Skip-link + `<main id="main-content">` route-change focus reset
    in [shell.ts](../../hospital-portal/src/app/shell/shell.ts).
  - Sidebar nav `Alt+ArrowUp` / `Alt+ArrowDown` keyboard reorder
    sharing the `moveNavItem` primitive with the existing mouse
    drag-drop.
  - `RovingFocusDirective` (vitals grid, patient-tracker rows,
    in-basket items) at
    [shared/a11y/roving-focus.directive.ts](../../hospital-portal/src/app/shared/a11y/roving-focus.directive.ts)
    with the AZERTY-friendly `Alt`-modifier mode for input groups.
  - Documented-palette contrast migration: every text-color use of
    `#9ca3af`, `#94a3b8`, `#cbd5e1` replaced with the documented
    tokens (`#6b7280`, `#64748b`) across 69 files.

### Internationalisation

- **FR completeness gate (row 12).** Tooling extracts every key
  from `*.json` translation files; CI fails any PR where a locale
  drops below 99% of EN coverage. Enforced in
  [.github/workflows/frontend-ci.yml](../../.github/workflows/frontend-ci.yml).
  At cut time FR is at full parity; ES is at the GA-acceptable
  threshold.

## What is NOT in v1.0.0-rc1

These are tracked for v1.0.0 GA polish or for the v1.1 horizon —
see [docs/roadmap.csv](../roadmap.csv) and
[docs/ui/accessibility.md §10 carry-forward](../ui/accessibility.md#10-known-gaps-tracked-for-v100-ga).

- **Wider color-contrast remediation.** Row 11 closed the documented
  forbidden-grey palette (`#9ca3af / #94a3b8 / #cbd5e1` foregrounds);
  the broader debt (`.btn-primary` light-blue backgrounds, language
  toggles, `.tab-bar` buttons, etc.) is a design-system pass tracked
  separately. The axe `color-contrast` rule remains suppressed in
  the CI smoke until that pass lands.
- **Adding `/reception`, `/nurse-station`, `/prescriptions`,
  `/pharmacy/dispensing` to the axe smoke.** Each carries the wider
  contrast debt above plus two structural bugs (`<input>` missing
  label on `/reception`; `<select>` missing accessible name on
  `/pharmacy/dispensing`).
- **Patient-tracker arrow-roving Playwright test.** The directive is
  unit-tested but the e2e is `test.skip` because the chromium
  project's storage state is hospital-agnostic SuperAdmin, so
  `auth.getHospitalId()` returns null and the board never renders.
  Re-enabled when a hospital-bound storage state fixture lands.
- **Sidebar drag-handle keyboard alt for nested groupings.** Out of
  scope for v1.0; the Alt+Arrow shortcut covers the primary use case.
- **Dashboard widget grid roving.** Currently the dashboard renders
  static panels; if a future polish pass adds a draggable widget
  grid, it will need the same `RovingFocusDirective` treatment.
- **WAI-ARIA `tabs` pattern (`aria-selected`) on in-basket filter
  tabs.** They get arrow-key roving in row 11; the formal tabs
  pattern is on the v1.1 list.
- **Forgot-password / forgot-username Playwright assertions for
  focus-trap + Escape close.** Manually verified, formalisation
  deferred to a v1.0.0 GA polish PR.
- **Anything in the v1.1 horizon** — FHIR write API, `$export`,
  `$everything`, ORU^R01 persistence, ADT sync, EMPI v0, mobile
  parity, KPI dashboards. See roadmap rows 14 – 26.

Flyway migration high-water mark is **`V96`** (the
`createAssignment` dedup migration that landed in PR #309), with
`V89` (`integration_message_event`) shipping as part of the MVP-c3
batch when its `develop → uat → main` promote chain completes
ahead of the cut.

`V88` + `V96` and the MVP-c3 work moves to v1.0.0-rc2 or v1.1
depending on timing. The release manager confirms the actual
high-water mark in the tag annotation.

## Soak window

`v1.0.0-rc1` enters a 7-day soak the moment the tag is pushed. The
freeze rules and promotion criteria are documented in
[docs/runbooks/release-soak-protocol.md](../runbooks/release-soak-protocol.md).
TL;DR:

- Only `fix/*`, `chore/*`, `docs/*` branches may merge.
- `feat/*` is frozen on the release branch (still allowed against
  `develop` for v1.1 work).
- Two clean overnight CI runs + one DR rehearsal must complete in
  the window.
- A blocker discovered during soak rolls into a hot `v1.0.0-rc2`
  cut; the soak clock resets.

## How to roll back

If post-soak deployment surfaces a blocker that wasn't caught in
the window:

1. Re-deploy the last green Railway snapshot taken before the
   `v1.0.0` promotion (snapshot ID lives in
   [docs/runbooks/disaster-recovery.md](../runbooks/disaster-recovery.md)).
2. Restore the database to the same point in time using the
   procedure in §3 of the DR runbook.
3. Move the `v1.0.0` tag back if needed:
   `git tag -d v1.0.0 && git push origin :refs/tags/v1.0.0`. The
   `v1.0.0-rc1` tag stays — it documents the historical attempt.

## Signing

Tags MUST be signed with the release manager's GPG key. The helper
script verifies `git config --get user.signingkey` is set and that
`git tag -s` succeeds before pushing. The signature is the only
machine-verifiable claim that the tagged commit was sanctioned by
the release manager rather than an opportunistic push.
